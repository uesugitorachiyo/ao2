# AO2 v0.4.81 AI Task Board Control Surface

AO2 `v0.4.81` starts the next patch release train after the stable `v0.4.80`
public release. The release theme is an AI task board and control surface that
keeps Pulse loops anchored to explicit operator-visible work instead of letting
generated task batches drift toward narrow recursive maintenance.

## Goals

- Make the next recommended task packet render as an operator task board with
  status, rationale, evidence, and stop conditions.
- Let local executor/evidence output advance task-board status through
  `AO2_PULSE_TASK_BOARD_STATUS_EVIDENCE` without giving the control plane write
  authority.
- Give every generated task-board task a concrete `next_action` so operators
  can see the next command or implementation step without reading the packet.
- Keep Pulse loops aligned to the current release objective so Pulse loops stop
  drifting after each batch.
- Preserve the existing trust boundary: the control plane is a read-only
  observer, and AO2 remains the owner of release acceptance evidence.
- Add a stable local artifact that can be consumed by the AO2 control plane
  without secrets or release mutation.

## Initial Tasks

1. Define the `ao2.ai-task-board.v1` schema for task id, objective, status,
   confidence, evidence requirements, stop conditions, source recommendation,
   and release-train linkage.
2. Extend `pulse:generate-next` so it can emit a task-board JSON packet and
   still preserve the existing recommended-task packet contract.
3. Add a read-only dashboard/export path for the task board that summarizes the
   current v0.4.81 release objective and why each task is next.
4. Add tests that reject task packets with no release objective, no evidence
   requirement, or no stop condition.
5. Add a control-plane fixture consumer smoke so the board can be read without
   granting the control plane write authority.
6. Persist task-board history and diffs so operators can see why the next
   task changed between Pulse generations.
7. Record field-level task diffs for objective, status, rationale, evidence,
   stop conditions, and title.
8. Render a catalog-backed `ao2.control-plane-operator-task-board-view.v1`
   HTML view from `control-plane:fixture-consumer-smoke`, with
   machine-readable `authority_boundary` and `trust_boundary` fields proving
   the control plane remains a read-only observer.
9. Emit executor-backed `ao2.ai-task-board-status-evidence.v1` from
   `pulse:task-executor` and validate it with
   `AO2_PULSE_NEXT_TASK_QUALITY_STATUS_EVIDENCE`.
10. Auto-discover AO2-local executor status evidence through
    `AO2_PULSE_TASK_EXECUTOR_ROOT` and publish compact
    `ao2.ai-task-board-state-summary.v1` board state.
11. Add stable task IDs so status evidence can carry across generated board
    generations while preserving generation-specific task IDs for traceability.
12. Add `npm run pulse:task-board-state` as a standalone, read-only board-state
    command that does not regenerate the next Pulse packet.
13. Render stale-generation status evidence as an explicit ignored warning in
    `board.md` and `board.html`.
14. Teach `pulse:next-task-quality-filter` the same `stable_task_id` evidence
    key semantics as `pulse:generate-next`, while preserving stale-generation
    and unknown-ID fail-closed checks.
15. Add `npm run pulse:next-actions` as a compact AO2-alone operator command for
    reading the current board's actionable next steps, with optional
    `AO2_PULSE_NEXT_ACTIONS_STATUS` filtering.
16. Emit failed board-state summaries for malformed board inputs and match
    telemetry for quality-filter status evidence.
17. Add a live local control-plane bridge smoke that POSTs the generated board
    to `/api/v1/ai/task-board`, reads `/api/v1/ai/task-board/latest` and
    `/api/v1/ai/task-board/dashboard.json`, and records token-free readback
    evidence.
18. Add a dual-repo installed release smoke that packages an installed AO2
    archive and an installed ao2-control-plane archive, extracts their binaries,
    POSTs the generated task board through the installed control plane, and
    records readback evidence without publishing or mutating release metadata.
19. Add `npm run pulse:task-board-closure-packet` to compose the task board,
    next-actions view, board-state view, and control-plane fixture readback into
    one fail-closed `ao2.pulse-task-board-closure-packet.v1` artifact.
20. Add verifier-only closure-packet fixtures so malformed evidence fails with
    explicit blockers for missing safety fields, task ID drift, and failed
    control-plane readback.

## Stop Conditions

- Stop if the task board can mutate AO2 artifacts or release metadata.
- Stop if generated tasks omit evidence requirements or stop conditions.
- Stop if the control-plane readback requires credentials or private local
  paths.
