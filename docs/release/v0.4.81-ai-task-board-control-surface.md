# AO2 v0.4.81 AI Task Board Control Surface

AO2 `v0.4.81` starts the next patch release train after the stable `v0.4.80`
public release. The release theme is an AI task board and control surface that
keeps Pulse loops anchored to explicit operator-visible work instead of letting
generated task batches drift toward narrow recursive maintenance.

## Goals

- Make the next recommended task packet render as an operator task board with
  status, rationale, evidence, and stop conditions.
- Keep Pulse loops aligned to the current release objective so Pulse loops stop
  drifting after each batch.
- Preserve the existing trust boundary: the control plane is a read-only
  observer, and AO2 remains the owner of release acceptance evidence.
- Add a stable local artifact that can be consumed by the AO2 control plane
  without secrets or release mutation.

## Initial Tasks

1. Define the `ao2.ai-task-board.v1` schema for task id, objective, status,
   confidence, evidence requirements, stop conditions, source recommendation,
   and release-train linkage.
2. Extend `pulse:generate-next` so it can emit a task-board JSON packet and
   still preserve the existing recommended-task packet contract.
3. Add a read-only dashboard/export path for the task board that summarizes the
   current v0.4.81 release objective and why each task is next.
4. Add tests that reject task packets with no release objective, no evidence
   requirement, or no stop condition.
5. Add a control-plane fixture consumer smoke so the board can be read without
   granting the control plane write authority.

## Evidence

- `PYTHONDONTWRITEBYTECODE=1 python3 -m pytest tests/test_public_stabilization.py -q`
- `npm run pulse:generate-next:contract`
- `npm run control-plane:fixture-consumer-smoke`
- A new `target/pulse-task-board/latest/summary.json` artifact using
  `ao2.ai-task-board.v1`.
- The first implementation writes `task-board.json` beside the existing Pulse
  packet artifacts so control-plane fixture consumers can read task-board state
  as local, credential-free evidence.

## Stop Conditions

- Stop if the task board can mutate AO2 artifacts or release metadata.
- Stop if generated tasks omit evidence requirements or stop conditions.
- Stop if the control-plane readback requires credentials or private local
  paths.
