# AO2 0.5 Evidence Migration

AO2 0.5 preserves existing event evidence while adding policy-integrity binding.
This is a versioned verification change, not permission to rewrite historical
records.

## Event Digests

- Events without `policy_integrity` continue to use
  `ao2.event.payload.v1`. Their stored payload digests remain valid.
- Events carrying `policy_integrity` use `ao2.event.policy-integrity.v2` and
  bind the policy identity, version, and digest into the event digest.
- Readers select the digest algorithm from the event shape. They must not
  reinterpret legacy events as policy-bound events or silently remove a
  policy-integrity binding.
- Replay fails closed when a required policy binding or digest changes.

No migration rewrites existing `.ao2/` evidence. New 0.5 runs emit the
policy-bound form where the policy decision supplies the binding. Consumers
must retain both verification paths for the 0.5 compatibility window.

## Producer/Consumer Gate

Run the compatibility gate from the AO2 checkout with the adjacent Control
Plane checkout, or set `AO2_CONTROL_PLANE_ROOT` explicitly:

```sh
AO2_CONTROL_PLANE_ROOT=../ao2-control-plane \
  scripts/evidence-compatibility-gate.sh
```

The gate verifies AO2's legacy and policy-bound digest vectors, the shared
canonical-JSON vectors, and Control Plane's exact-byte evidence-pack ingestion.
It performs no provider call and does not mutate stored evidence.
