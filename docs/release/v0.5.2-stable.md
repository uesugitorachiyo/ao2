# AO2 v0.5.2 Stable Patch Release Notes

AO2 `v0.5.2` is a stable patch release for the AO2 `v0.5` line.

Release URL: <https://github.com/uesugitorachiyo/ao2/releases/tag/v0.5.2>

Compatible stable companion:
[AO2 Control Plane v0.1.17](https://github.com/uesugitorachiyo/ao2-control-plane/releases/tag/v0.1.17).

## Why This Patch Exists

AO2 `v0.5.1` remains a verified stable release, but post-release work added
operator-facing GitHub issue intake, acquisition readback, and repair evidence
fixtures for the issue-to-draft-PR workflow. AO2 `v0.5.2` publishes those
shipped CLI and support-path changes in stable public binaries.

## Included Changes

- GitHub issue intake validates public issue URLs for the controlled
  issue-to-draft-PR workflow.
- GitHub issue acquisition readback records a bounded plan for an authenticated
  issue without approving, merging, or contacting external maintainers.
- Wrong-repository and invalid-target paths remain denied with no writes.
- Repair evidence fixtures are available for downstream Control Plane
  observation.
- AO2 `v0.5.2` is paired with AO2 Control Plane `v0.1.17`.

## Public Assets

The release publishes archives for:

- macOS aarch64
- Linux x86_64
- Linux aarch64
- Windows x86_64

The public asset set also includes `SHA256SUMS`, CycloneDX SBOMs, detached
signatures, signed provenance, release readiness JSON, and release-train bridge
evidence.

## Verification

Before installing, download the release assets and run:

```sh
shasum -a 256 -c SHA256SUMS
```

After extracting the archive, run `./verify-release.sh` on macOS/Linux or
`.\Verify-Release.ps1` on Windows. Then install and confirm:

```sh
ao2 version --json
ao2 doctor --json
```

If the new binary needs to be rolled back after an install/update, run:

```sh
ao2 install rollback
```

See [Install And Update Guide](../INSTALL.md) and
[Public Release Verification](PUBLIC-RELEASE-VERIFICATION.md) for the operator
workflow.

## Boundaries

This patch release does not approve or merge feature-generated pull requests,
does not contact external maintainers, does not require a new Control Plane
release, does not grant release approval authority to the control plane, does
not require provider API keys for the first-run path, and does not publish
provider pilot results.

RSI remains denied.
